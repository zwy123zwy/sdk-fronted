# C06 队列与调度：验收用例

对应任务：T15。时间相关用例使用假定时器。

| 用例 | 需求 | 前置 / 操作 | 预期结果 |
|---|---|---|---|
| C06-AC-01 | C06-F1 | 发送暂停时入队 600 条 normal 事件 | 队列保留最新 500 条；计数 `queue_evicted` 为 100 |
| C06-AC-02 | C06-F1 | 入队总体积超过 512 KB | 按体积上限淘汰最早的 normal 事件 |
| C06-AC-03 | C06-F1 | 队列已满时入队 critical 事件 | critical 事件不被淘汰；被挤出的是 normal 事件；全是 critical 时转入离线存储 |
| C06-AC-04 | C06-F2 | 连续入队 20 条 | 立即冲刷一个批次 |
| C06-AC-05 | C06-F2 | 入队体积达到 32 KB（不足 20 条） | 立即冲刷 |
| C06-AC-06 | C06-F2 | 入队 1 条后静默 1 秒；另测每 500 ms 入队一条持续 6 秒 | 前者 1 秒后冲刷；后者在第 5 秒因最长等待冲刷 |
| C06-AC-07 | C06-F2 | 页面触发 `visibilitychange` 为 hidden；另测 `pagehide` | 同步冲刷，并使用页面离开通道 |
| C06-AC-08 | C06-F2 | 业务调用 `flush` | 立即冲刷 |
| C06-AC-09 | C06-F3 | 批次内所有事件的 `page_id` 相同、`url` 不同 | `page_id` 提升到 `common`，`url` 保留在事件体；批次通过 `batch.schema.json` 校验 |
| C06-AC-10 | C06-F4 | 一个批次在途时又满足冲刷条件 | 不发出第二个常规批次；新事件继续入队；在途批次完成后再冲刷 |
| C06-AC-11 | C06-F5 | 模拟 `effectiveType` 为 `2g` 或 `saveData` 为 true | 批次条数上限和静默时间按配置放大 |
