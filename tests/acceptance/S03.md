# S03 埋点字典与 Schema 注册：验收用例

对应任务：T22。规则见 `docs/contracts/dictionary-compat.md`。

| 用例 | 需求 | 前置 / 操作 | 预期结果 |
|---|---|---|---|
| S03-AC-01 | S03-F1 | 提交 `event-definition.valid.json` | 保存成功，状态为 draft |
| S03-AC-02 | S03-F1 | 提交 `event-definition.invalid.json` 中的每个 case | 都被拒绝，并给出具体字段的错误 |
| S03-AC-03 | S03-F2 | 对兼容性规则表的每一行提交“旧 / 新”版本对 | 判定结果与规则表一致 |
| S03-AC-04 | S03-F2 | 修改字段而不递增 `schema_version` | 被拒绝 |
| S03-AC-05 | S03-F3 | 新增事件；提交破坏性变更 | 需要数据负责人审批后才能变为 active |
| S03-AC-06 | S03-F3、Q3 | 新增 critical 事件，导致应用 critical 占比超过配额 | 评审流拒绝 |
| S03-AC-07 | S03-F4 | 发布字典 | 生成类型包，版本号按兼容性递增；类型包可以被 `tsc` 使用 |
| S03-AC-08 | S03-F5 | S04 按 `event_name` + `schema_version` 查询规则，第二次带 `If-None-Match` | 第一次返回规则与 `ETag`；第二次返回 304 |
| S03-AC-09 | S03-F6 | S04 回传 3 个未登记事件名 | 出现在待认领清单中，带首次出现时间与次数 |
| S03-AC-10 | S03 安全 | 只读成员修改定义；任何修改 | 前者被拒绝；后者写入审计日志 |
