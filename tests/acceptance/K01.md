# K01 事件注册表与类型生成 CLI：验收用例

对应任务：T22。规则见 `docs/contracts/dictionary-compat.md`，元模型见 `schemas/event-definition.schema.json`。部分用例改编自已废弃的 `S03.md`。CLI 失败时必须返回非零退出码，并指出出错的文件与字段路径。

| 用例 | 需求 | 前置 / 操作 | 预期结果 |
|---|---|---|---|
| K01-AC-01 | K01-F1 | 校验只含 `event-definition.valid.json` 的注册表 | 退出码 0 |
| K01-AC-02 | K01-F1 | 逐个校验 `event-definition.invalid.json` 中的 case | 每个都返回非零退出码，错误信息包含字段路径 |
| K01-AC-03 | K01-F2 | 对兼容性规则表每一行准备“基线 / 新版本”样例对，运行检查 | 判定结果（兼容 / 破坏性 / 不递增版本）与规则表逐行一致 |
| K01-AC-04 | K01-F2 | 修改字段而不递增 `schema_version` | 非零退出码，提示需要递增版本 |
| K01-AC-05 | K01-F2 | 提交破坏性变更（递增了版本） | 非零退出码，除非传入 `--allow-breaking`；输出列出每一处破坏性变更 |
| K01-AC-06 | K01-F3、Q3 | 20 个事件中 2 个 critical；再加 1 个 critical | 前者通过；后者（3/21 > 10%）非零退出码 |
| K01-AC-07 | K01-F1 | 两个文件定义同名同版本的事件；事件名使用 `web_` 前缀 | 都返回非零退出码 |
| K01-AC-08 | K01-F4 | 生成类型声明，用 `tsc --noEmit` 编译一组正确与错误的调用样例 | 正确样例编译通过；未登记事件名、缺必填字段、类型错误、枚举值错误都报错；生成文件不含运行时代码 |
| K01-AC-09 | K01-F4 | 检查生成的类型 | 每个事件名携带 `priority` 与 `schema_version` 字面量类型；只包含 `active` 事件的最新版本 |
| K01-AC-10 | K01-F5 | 导出校验规则 JSON | 输出符合工具自带的规则 Schema；每个事件保留最近 3 个版本 |
| K01-AC-11 | K01-F6 | 输入 M01 导出的事件名清单，含 2 个注册表中没有的事件 | 报告列出这 2 个事件及出现次数；退出码 0 |
| K01-AC-12 | K01 非功能 | 500 个事件定义的检查与生成 | 总耗时不超过 5 秒 |
