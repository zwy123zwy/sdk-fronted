# C07 传输与可靠投递：验收用例

对应任务：T16。协议细节见 `docs/contracts/ingest-protocol.md`。单元层用 mock 服务与假定时器，浏览器行为相关的用例（AC-03、AC-13、AC-15 至 AC-18）在 `tests/e2e/` 中用真实浏览器执行。

| 用例 | 需求 | 前置 / 操作 | 预期结果 |
|---|---|---|---|
| C07-AC-01 | C07-F1 | 常规冲刷 | 使用 `fetch` keepalive；请求头含 `X-App-Id`、`X-Write-Token`；令牌不出现在 URL |
| C07-AC-02 | C07-F1 | 浏览器不支持 keepalive | 降级为 `XMLHttpRequest` |
| C07-AC-03 | C07-F1 | 页面离开时冲刷 80 KB 数据 | 使用信标通道，拆成至少两个不超过 60 KB 的请求；`Content-Type` 为 `text/plain`；令牌在 `auth` 字段 |
| C07-AC-04 | C07-F2 | 服务端返回 202 | 视为成功；删除离线副本 |
| C07-AC-05 | C07-F2 | 返回 400 | 丢弃并计数 `rejected_400`；不重试 |
| C07-AC-06 | C07-F2 | 返回 401；之后配置更新了令牌 | 暂停发送；配置更新后恢复；暂停期间事件入队不丢 |
| C07-AC-07 | C07-F2 | 返回 413 | 拆成两半重发，`event_id` 不变、`batch_id` 重新生成；单条仍超限时丢弃该条 |
| C07-AC-08 | C07-F3 | 返回 429，`Retry-After: 7` | 7 秒后重试（取与本地退避的较大值） |
| C07-AC-09 | C07-F3 | 连续返回 503 | 按 1、2、4 秒（±20% 抖动）重试 3 次，之后落盘；`batch_id` 保持不变 |
| C07-AC-10 | C07-F4 | 连续 5 个批次失败 | 熔断 5 分钟，期间只入队不发送，计数 `circuit_open`；之后放行一个探测批次 |
| C07-AC-11 | C07-F4 | 401、403 不计入熔断 | 连续 5 次 401 不触发熔断，走暂停逻辑 |
| C07-AC-12 | C07-F5 | 发送含 critical 事件的批次，在响应前模拟页面强杀 | 离线存储中保留该批次；下次启动后补发，服务端只入库一次 |
| C07-AC-13 | C07-F5 | 页面离开时用信标发送 critical 批次，`sendBeacon` 返回 true | 离线副本不删除，下次启动由常规通道补发确认 |
| C07-AC-14 | C07-F6 | 断网 10 分钟期间上报 3 个 critical 事件，然后恢复联网 | 恢复后补发，`replayed: true`，补发速率不超过每秒 2 个批次 |
| C07-AC-15 | C07-F6 | 页面从隐藏变为可见；另测重新打开页面 | 都触发补发 |
| C07-AC-16 | C07-F6 | 离线存储超过 2,000 批或 5 MB；另测超过 7 天 | 淘汰最早的批次，计数 `offline_evicted` |
| C07-AC-17 | C07-F7 | 同一应用打开 3 个标签页，各有离线数据 | 只有主标签页补发；主标签页关闭后另一个接替 |
| C07-AC-18 | C07-F7 | 浏览器不支持 Web Locks | 降级为广播通道选主；仍不支持时各自补发，依靠服务端去重 |
| C07-AC-19 | C07-F8 | 批次 3 KB 与 6 KB 各一个，浏览器支持 `CompressionStream` | 3 KB 不压缩；6 KB 压缩并带 `Content-Encoding: gzip` |
| C07-AC-20 | C07-F9 | 注入自定义传输与存储适配器 | 使用注入的适配器发送与存储 |
| C07-AC-21 | C07 安全 | 撤回同意或注销 | 离线数据清空；离线数据中从未出现未脱敏内容 |
| C07-AC-22 | C07 安全 | 离线数据的格式版本与当前 SDK 不兼容 | 清理旧数据，不抛错 |
