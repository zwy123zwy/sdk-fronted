# C02 内核与插件宿主：验收用例

对应任务：T11。

| 用例 | 需求 | 前置 / 操作 | 预期结果 |
|---|---|---|---|
| C02-AC-01 | C02-F1 | 依次调用初始化、启动、销毁 | 状态依次为已初始化、运行中、已销毁 |
| C02-AC-02 | C02-F1 | 未初始化时调用启动；已销毁后调用初始化 | 都被忽略，状态不变，不抛错 |
| C02-AC-03 | C02-F1 | 运行中触发暂停（撤回同意），再恢复 | 状态为暂停 → 运行中；暂停期间按原因不采集或不发送 |
| C02-AC-04 | C02-F2 | 注册六段处理器，各自给事件加一个标记 | 事件按校验、富化、过滤、采样、构建、发送前的顺序经过，标记顺序正确 |
| C02-AC-05 | C02-F2 | 过滤段处理器返回“终止，原因 `filtered_by_plugin`” | 事件不进入后续段；计数 `filtered_by_plugin` 加 1 |
| C02-AC-06 | C02-F3 | 富化段的一个处理器抛错 | 跳过该处理器，事件继续；计数 `processor_error` 加 1；错误不出现在 `window.onerror` |
| C02-AC-07 | C02-F4 | 注册一个依赖不存在插件的插件 | 该插件不安装并计数，其他插件正常安装 |
| C02-AC-08 | C02-F4 | 插件安装函数抛错 | 其他插件不受影响；SDK 继续运行 |
| C02-AC-09 | C02-F4 | 配置关闭一个已安装的插件 | 插件卸载，它注册的监听和 hook 全部释放 |
| C02-AC-10 | C02-F5 | 配置就绪前上报 600 条 normal 事件 | 预启动队列保留最新 500 条；计数 `prestart_queue_overflow` 为 100；配置就绪后按顺序回放 |
| C02-AC-11 | C02-F5 | 配置就绪前上报 critical 事件导致溢出 | critical 事件不被淘汰，淘汰的是最早的 normal 事件 |
| C02-AC-12 | C02-F6 | 两个插件都订阅 `error` 事件 | `window.addEventListener('error')` 只被调用一次；两个插件都收到事件 |
| C02-AC-13 | C02-F6 | 业务先 hook `history.pushState`，SDK 再 hook，然后 SDK 销毁 | 销毁后 `pushState` 恢复为业务的包装函数，而不是原生函数 |
| C02-AC-14 | C02-F1、C02-F6 | 销毁后检查 | 没有残留的监听、定时器、hook；之后调用任何公共方法都计数 `destroyed`，不抛错 |
