# 验收用例规格

本目录按需求编号编写验收用例，是执行 Agent 开工前必须对照的标准（指南第 5 节第 5 步）。

- 编写与维护：A09；执行 Agent 不得修改本目录（指南第 9 节）。
- 当前状态：**规格稿**。仓库与测试框架由 T08 初始化后，A09 在任务开工前把对应用例转成可执行测试，测试名以用例编号开头（如 `C07-AC-03 ...`），以便和本目录一一对应。
- 每条用例对应一个需求编号；一个需求可以有多条用例。“必须”级需求 100% 通过，“应该”级需求不低于 90%（总体方案“质量验收体系”）。
- 用例编号格式：`<模块>-AC-<两位序号>`，如 `C07-AC-03`。编号一经发布不再复用；删除的用例标注“已废弃”。

## 原因码覆盖

`docs/contracts/reason-codes.md` 第 1、2 节的每个原因码都标注了验收用例编号。新增原因码时必须同时新增或指明用例；C08-AC-01 逐个触发第 1 节的丢弃原因码，核对计数。

## 用例格式

| 用例 | 需求 | 前置 / 操作 | 预期结果 |
|---|---|---|---|

“前置 / 操作”写清环境和输入；“预期结果”必须可以机器判定（计数、状态、返回值、请求内容），不写“正常工作”这类描述。
