# Q7 迁移期是否保留第三方 APM 的错误与性能监控

- 状态：已确认
- 确认人：wenye.zhang
- 确认日期：2026-10-09

## 问题

接入方可能已经在使用第三方 APM 采集错误、性能和 HTTP 数据。迁移期间，两套 SDK 同时 hook 全局对象（`window.onerror`、`fetch`、`XMLHttpRequest`、`history`），存在冲突风险（R01），也会重复采集。

## 建议方案

1. **迁移期保留第三方 APM 的错误与性能监控**，直到本 SDK 的 C05 插件在该接入方连续 7 天对账达标。
2. **共存期间默认关闭本 SDK 中与第三方 APM 重叠的插件**：错误、性能、HTTP 插件默认关闭，只启用自定义事件、页面浏览和自监控。接入方可以通过远程配置逐个开启，开启后进入对账。
3. **双写适配器（C05-F5）是单向的**：本 SDK 的自定义事件可以转发给第三方 APM，不从第三方 APM 读取数据。
4. **hook 冲突的处理**：本 SDK 不论初始化早晚，都要和已安装的第三方 hook 正常协作；卸载时只还原自己装上的那一层。T18 必须包含“与第三方 APM 共存”的专项用例，T30 在兼容性矩阵中覆盖。

## 备选方案与取舍

- 立即用本 SDK 替换第三方 APM：省去重复成本，但错误监控在对账达标前没有兜底。
- 同时开启两边的全部插件：数据最全，但重复采集和 hook 冲突的风险最高。

## 如果结论与建议不同，需要改什么

- `docs/contracts/schemas/remote-config.schema.json` 中插件的默认开关。
- T18、T19 任务卡；`tests/acceptance/C05.md` 中的共存用例。

## 结论

采纳建议方案，第 1–4 条全部保留。
