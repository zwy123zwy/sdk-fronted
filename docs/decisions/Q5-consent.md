# Q5 用户同意交互与默认采集策略

- 状态：已确认（SDK 默认行为；各接入方的合规责任见结论）
- 确认人：wenye.zhang
- 确认日期：2026-10-09

## 问题

C04-F5 要求“未同意前只采集必要的匿名事件，或只缓存不发送（可配置）”。需要确定：同意由谁收集、默认策略是什么、什么算“必要的匿名事件”。

## 建议方案

1. **同意由接入方收集**：SDK 不提供同意弹窗，只提供设置同意状态的方法。同意状态有三种：`granted`（已同意）、`denied`（已拒绝）、`unknown`（未表态）。
2. **默认状态**：初始化时为 `unknown`，接入方可以在初始化参数中传入已知状态。
3. **各状态下的行为**：

| 状态 | 采集 | 发送 | 本地标识 |
|---|---|---|---|
| `unknown` | 按配置的 `consent_mode` 处理，默认为 `essential_only` | 只发送必要事件 | 不生成持久化设备标识，只用内存中的会话标识 |
| `granted` | 全部 | 全部 | 生成并持久化设备标识 |
| `denied` | 只采集必要事件 | 只发送必要事件 | 清除设备标识、离线数据和会话随机数 |

4. **必要事件**：不包含任何用户标识、设备标识和自定义维度的 SDK 健康事件（`sdk_health`），以及经过脱敏、去掉堆栈中 URL 查询参数的 JS 错误计数。具体清单在 T07 中写进配置契约。
5. **`consent_mode` 可选值**：`essential_only`（默认）、`buffer`（先缓存不发送，同意后补发，缓存上限沿用离线存储上限，拒绝时清空）、`full`（接入方声明已取得授权时使用，需要在控制台中由应用负责人确认）。

## 备选方案与取舍

- 默认 `full`：数据最完整，但在需要事先同意的地区不合规。
- 默认 `buffer`：用户同意后数据不丢，但用户长期不表态时会持续占用本地存储。

## 如果结论与建议不同，需要改什么

- `docs/contracts/schemas/remote-config.schema.json` 中的 `privacy.consent_mode`。
- T07、T14 任务卡；`tests/acceptance/C04.md` 中的同意相关用例；T31 的隐私测试范围。

## 结论

采纳建议方案，作为 SDK 的默认行为：

- SDK 默认 `consent_mode` 为 `essential_only`，初始同意状态为 `unknown`；
- 接入方可以在初始化参数或远程配置中改为 `buffer` 或 `full`。

**接入方必须自行确认合规。** SDK 只提供机制和保守的默认值，不判断接入方的业务是否已经取得授权。T34 的接入指南必须写明这一点，并且在 `full` 模式的说明中注明“需要接入方的法务确认”。
