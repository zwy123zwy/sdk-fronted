# CR-004 统一失败表的「生效配置」语义，并把 WebCrypto 例外显式化

- 状态：**已批准（2026-10-13）**，已应用到 `docs/contracts/remote-config.md` 第 3 节失败表
- 起草人：A01（编排方代行）；起草日期：2026-10-13
- 来源：T13（C03）在 M2–M5 完成后的失败表逐行核对（编排方应 CR-003 的 AC-24 修正要求它做的）
- 流程依据：`docs/contracts/README.md`「契约冻结后，修改走契约变更请求：A01 起草，架构负责人批准」

## 1. 问题

`remote-config.md` 第 3 节的失败表里，「拒绝本次配置」之后使用哪份配置，**各行措辞不一致**：

| 行 | 原文 | 问题 |
|---|---|---|
| 签名校验失败 | 「拒绝本次配置，**继续使用当前生效配置**；没有可用配置时使用保守默认」 | 语义完整 |
| `config_version` 不大于当前 | 「拒绝本次配置，**保持当前配置**」 | 语义完整 |
| scope 不符 / format 不支持 / parse 失败 | 「同签名校验失败」 | 语义完整（引用） |
| **网络失败、5xx，没有缓存** | 「**使用保守默认**」 | **未写「有当前配置则保持」** |
| **运行环境不支持 WebCrypto** | 「不校验签名，只使用保守默认」 | 与通则不同，但未声明为例外 |

**风险**：若按字面实现第 4 行，**一次网络抖动就能把已经生效的远程配置打回保守默认**（只保留 critical 与 JS 错误采集、其他插件关闭）——相当于对数据管道的一次拒绝服务。同一个坑在 CR-003 的 `C03-AC-24` 初版措辞里也出现过（编排方写作「退回保守默认」），由 T13 在 M0 计划评审时指出并已修正。

第 5 行（WebCrypto 不可用）**确实应当与通则不同**：无法验签时不能信任任何配置（包括缓存里那份），所以即使有当前生效配置也必须退回保守默认。但原表未把它声明为例外，实现者可能按通则处理。

## 2. 精确改动

### 2.1 网络失败行

> | 网络失败、5xx，没有缓存 | 拒绝本次配置：**有当前生效配置则保持，无则使用保守默认** | `config_fetch_failed` | C03-AC-06 |

### 2.2 表下新增通则

> **生效配置语义的通则**：除上表最后一行（WebCrypto 不可用）这一**唯一例外**外，本表所有「拒绝本次配置」的行统一遵循——**有当前生效配置时保持该配置不变；只有没有任何可用配置时才使用保守默认**。

并写明立此通则的原因（避免"推送非法配置或制造网络抖动即可把 SDK 打回最保守模式"的降级面）。

### 2.3 WebCrypto 行显式标注为例外

> | 运行环境不支持 WebCrypto | **唯一例外**：不校验签名，**即使存在缓存或当前生效配置也只使用保守默认** | `config_signature_unavailable` | C03-AC-20 |

### 2.4 版本记录

按既有先例标注「0.2（兼容追加）」、**不递增文档版本号**。

## 3. 兼容性判定

| 判据 | 本次改动 | 结论 |
|---|---|---|
| 行为语义 | 把大多数行的既有语义**提取为通则**；只把「网络失败且无缓存」一行的行为明确为「有当前配置则保持」 | 兼容（该行原文未定义"有当前配置"的情形，无既有实现依赖旧读法） |

## 4. 备选方案与取舍

| 方案 | 优点 | 代价 |
|---|---|---|
| **统一为通则 + 例外显式化**（采纳） | 实现者不会再从模糊描述里猜；杜绝降级面；后续新增失败行只需声明是否例外 | 需要改契约（本次已在走 CR 流程） |
| 只改网络失败那一行 | 改动最小 | WebCrypto 例外的特殊性仍未声明，下一个实现者可能按通则把它做成"保持当前配置"，**而这会让无法验签的缓存被继续使用** |
| 不改契约、由 C03 在 README 里写实现口径 | 零流程成本 | 契约与实现不一致；接收方与后续实现者仍会误读 |

## 6. 范围补充（2026-10-13 同日，T13 在 M6 复核时提出）

表**第一行**「网络失败、5xx，有未过期缓存 → 使用本地缓存」也应纳入本次的统一：若已有**更新的生效配置**（例如本会话内成功拉取过），却因一次网络失败去采用**较旧的缓存**，会造成**版本回退**——可能把新版本故意关闭的插件重新打开、或恢复更宽松的采样。已改为：

> | 网络失败、5xx，有未过期缓存 | 优先**保持当前生效配置**；仅在没有任何可用配置时才采用该缓存 | `config_fetch_failed` | C03-AC-05 |

**该澄清在正常实现下不产生行为差异**：每次成功拉取后都会更新缓存，因此"当前生效配置"与"缓存"不会出现新旧倒挂；本条只是把优先顺序写明，避免实现者按字面"总是用缓存"写出回退路径。CR-004 的目的本是统一这张表的生效配置语义，第一行属当时遗漏。
