# 上报协议 I-01

- 版本：0.1（草案，未冻结）
- 对应任务：T05；需求：C07-F1、C07-F2、C07-F8、S01-F1 至 S01-F6
- 提供方：S01 接入网关；调用方：C07 传输模块

## 1. 端点

| 项 | 值 |
|---|---|
| 方法 | `POST` |
| 路径 | `/v1/batch`；主版本号体现在路径中 |
| 协议 | 必须是 HTTPS（TLS 1.2 及以上） |
| 端点来源 | 初始化参数 `endpoint`，远程配置 `endpoints.ingest` 可以覆盖；SDK 不得内置默认域名 |

## 2. 请求

### 2.1 常规通道（fetch keepalive 或 XMLHttpRequest）

| 请求头 | 必填 | 说明 |
|---|---|---|
| `Content-Type` | 是 | `application/json` |
| `Content-Encoding` | 否 | 压缩时为 `gzip`。只有批次序列化后超过 4 KB、且浏览器支持 `CompressionStream` 时才压缩（C07-F8） |
| `X-App-Id` | 是 | 应用标识，必须与请求体中的 `app_id` 一致 |
| `X-Write-Token` | 是 | 只写令牌 |
| `X-Request-Id` | 否 | 与请求体 `batch_id` 相同，便于服务端日志关联 |

请求体为一个批次，结构见 `schemas/batch.schema.json`。

### 2.2 信标通道（页面离开时）

`navigator.sendBeacon` 不能设置自定义请求头，也不能设置 `Content-Encoding`。因此：

- 请求体不压缩，`Content-Type` 为 `text/plain;charset=UTF-8`，内容为批次 JSON。使用 `text/plain` 是为了避免触发跨域预检。
- 令牌放在请求体的 `auth.write_token` 字段，`auth.app_id` 与批次的 `app_id` 一致。**令牌不得放在 URL 中。**
- 请求体不得超过 60 KB（C07-F1 预先切片的上限），超过时由 C07 拆分成多个信标请求。
- 网关通过 `Content-Type` 识别信标通道，从请求体读取令牌；常规通道的请求体中出现 `auth` 字段时，网关必须忽略它，只认请求头。

**待评审**：信标通道把令牌放在请求体中，与总体方案“令牌放在请求头而不是 URL 中”的要求在字面上不完全一致，但满足其本意（令牌不进入 URL 与访问日志）。需要在 T05 评审时由安全负责人确认。

### 2.3 限制

| 项 | 上限 | 超限时 |
|---|---|---|
| 请求体（解压后） | 1 MB | 413 |
| 请求体（压缩后，常规通道） | 256 KB | 413 |
| 单批事件数 | 500 | 413 |
| 单条事件序列化后 | 16 KB | 该条拒绝，原因码 `event_too_large`，其余事件正常处理 |

单条事件超限的检查放在 S04；S01 只检查整批限制，保证网关逻辑轻量。

## 3. 响应

### 3.1 响应码

| 响应码 | 含义 | 客户端行为 | 原因码（C08 计数） |
|---|---|---|---|
| 202 | 批次已写入消息队列 | 视为成功，删除离线副本 | — |
| 400 | 批次结构非法、协议版本不支持、`app_id` 不一致 | 丢弃并计数，不重试 | `rejected_400` |
| 401 | 令牌无效或已吊销 | 丢弃并计数；暂停发送，直到下一次配置拉取成功并且令牌或端点发生变化 | `rejected_401` |
| 403 | 来源域名不在白名单、应用被停用 | 同 401 | `rejected_403` |
| 413 | 请求体或事件数超限 | 拆成两半重发；单条事件仍然超限时丢弃该条 | `rejected_413` |
| 429 | 限流 | 按 `Retry-After` 退避重试 | `retry_429` |
| 5xx | 服务暂时不可用（含消息队列不可用时的 503） | 指数退避重试，超过次数后落盘待补发 | `retry_5xx` |
| 网络错误、超时 | — | 同 5xx | `retry_network` |

其他未列出的 4xx 按 400 处理。信标通道无法读取响应：`sendBeacon` 返回 `true` 只表示浏览器接受了请求，C07 对 critical 批次不得因此删除离线副本，等下一次正常通道的补发确认（见 C07-F5）。

**网关必须只在批次写入消息队列成功后才返回 202**（S01-F4）。任何失败都不能返回 2xx。

### 3.2 响应头

| 响应头 | 出现条件 | 说明 |
|---|---|---|
| `Retry-After` | 429、503 | 秒数，整数。客户端取它与本地退避时间中的较大值，上限 60 秒 |
| `X-Server-Time` | 所有响应 | 服务端当前 UTC 毫秒时间戳，用于时钟校准（C04-F7） |
| `X-Request-Id` | 所有响应 | 回显请求的 `X-Request-Id`；请求中没有时由网关生成 |

### 3.3 响应体

202 时响应体可以为空。4xx 和 5xx 时为：

```json
{ "error": "payload_too_large", "message": "batch exceeds 500 events" }
```

`error` 取值见 `reason-codes.md` 第 3 节。客户端不得依赖 `message` 的内容。

## 4. 重试与幂等

- 客户端重试时必须保持 `batch_id` 和每条事件的 `event_id` 不变；拆分重发时生成新的 `batch_id`，`event_id` 不变。
- 服务端按“`app_id` + `event_id`”在 7 天窗口内去重（S04-F2），所以同一事件重复送达不会重复入库。
- 退避：首次 1 秒，倍数 2，上限 60 秒，最多 3 次，带 ±20% 的随机抖动（C07-F3）。
- 熔断：连续 5 个批次失败后暂停发送 5 分钟，只入队不发送，之后放行一个探测批次（C07-F4）。401、403 不计入熔断，走暂停逻辑。

## 5. 网关附加信息（I-03，S01 → S04）

网关写入消息队列的消息，在原始批次之外附加以下字段，客户端不可见：

| 字段 | 说明 |
|---|---|
| `received_at` | 网关接收时间，UTC 毫秒 |
| `client_ip_truncated` | IPv4 去掉末段（`a.b.c.0`），IPv6 保留前 48 位；完整 IP 不得写入消息 |
| `user_agent` | 请求头 `User-Agent` 原文 |
| `gateway_instance` | 网关实例标识 |
| `channel` | `fetch`、`xhr` 或 `beacon` |

消息键为 `app_id`，投递语义为至少一次。信标通道的 `auth` 字段必须在写入消息前删除。

## 6. 待评审问题

1. 信标通道的令牌位置（见 2.2）。
2. 压缩后 256 KB 的上限是否与网关解压的资源占用匹配，由 POC-2 确认。
3. 是否需要支持 `Content-Encoding: deflate` 或 `br`。草案只支持 `gzip`，因为 `CompressionStream` 普遍支持 gzip。
