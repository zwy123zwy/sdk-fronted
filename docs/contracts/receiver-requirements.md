# 接收方要求

- 版本：0.2（已冻结，2026-10-10；批准见 `README.md`“冻结记录”）
- 对应任务：T05；依据：`docs/decisions/D001-scope.md`
- 适用对象：在生产环境接收本 SDK 上报数据的服务（由接入方或其他团队提供）。本项目的 M01 mock 接收服务（T09）实现全部“必须”条目，只用于测试。

本 SDK 只负责客户端一侧。critical 事件“丢失率不超过 0.1%”和“不重复入库”的端到端目标，只有在接收方满足本文“必须”条目时才成立。接收方按本文自查；本项目不验证接收方的实现。

## 1. 协议

| 编号 | 要求 | 级别 | SDK 依赖的原因 |
|---|---|---|---|
| RR-01 | 实现 `ingest-protocol.md` 第 1–3 节的端点、请求格式、上限与响应码 | 必须 | C07 按响应码决定重试、拆分、丢弃 |
| RR-02 | 只在批次已持久化（写入队列或存储）之后返回 202；任何失败都不得返回 2xx | 必须 | SDK 收到 202 后删除 critical 离线副本，提前返回会造成丢失 |
| RR-03 | 同时支持常规通道（令牌在 `X-Write-Token` 请求头）和信标通道（`text/plain`，令牌在请求体 `auth` 字段）；常规通道请求体中的 `auth` 必须忽略 | 必须 | 页面离开时只能用信标 |
| RR-04 | 支持 `Content-Encoding: gzip`；流式解压，解压量达到 1 MB 立即中止并返回 413（防 gzip 炸弹）；压缩后超过 256 KB 直接返回 413；其他编码返回 400 | 必须 | C07-F8 压缩 |
| RR-05 | 按 `app_id` + `event_id` 在至少 7 天窗口内去重 | 必须 | SDK 为保证不丢失会重复送达（重试、补发、多标签页），去重由接收方完成 |
| RR-06 | 按 `event-standard.md` 的提升规则还原批次 `common` 字段；事件体中的值优先 | 必须 | SDK 会把公共字段提升到 `common` 以减小体积 |
| RR-07 | 429、503 返回 `Retry-After`；所有响应返回 `X-Server-Time` | 应该 | 退避与时钟校准（C04-F7） |
| RR-08 | 支持 CORS：允许 SDK 所在页面的来源、`POST`、`Content-Type`、`Content-Encoding`、`X-App-Id`、`X-Write-Token`、`X-Request-Id`；暴露 `Retry-After`、`X-Server-Time` | 必须 | 跨域上报 |

## 2. 安全

| 编号 | 要求 | 级别 |
|---|---|---|
| RR-11 | 只接受 HTTPS（TLS 1.2 及以上） | 必须 |
| RR-12 | 令牌只写不读，按应用签发，可吊销；吊销后返回 401 | 必须 |
| RR-13 | 访问日志与错误日志不记录令牌、信标请求体中的 `auth` 字段、完整 IP；`auth` 字段在持久化前删除；如需保存 IP，IPv4 去掉末段、IPv6 只保留前 48 位 | 必须 |
| RR-14 | 校验来源域名白名单，不匹配时返回 403 | 应该 |
| RR-15 | 对外接口限流，超限返回 429 而不是丢弃 | 应该 |

## 3. 数据

| 编号 | 要求 | 级别 |
|---|---|---|
| RR-21 | 按 `event-standard.md` 校验公共字段；不合规的事件进入死信或单独计数，不静默丢弃 | 应该 |
| RR-22 | 可以使用 K01 导出的校验规则做运行期校验（`dictionary-compat.md`） | 可以 |
| RR-23 | 保留 `sdk_health` 事件，供 SDK 一侧计数与入库计数对账（Q6） | 必须 |

## 4. 容量建议（不作为本项目验收标准）

依据 Q1 的参考值：首年日活设备 50 万，日均 5,000 万条事件，峰值 2 万条/秒，平均每批 15 条（约 1,500 个请求/秒），建议按 3 倍余量规划。SDK 单页面峰值约每秒 30 条事件。
