# 事件注册表兼容性规则（K01-F2）

- 版本：0.2（已冻结，2026-10-10；批准见 `README.md`“冻结记录”）
- 对应任务：T06、T22

接入方在自己仓库的 `events/*.json` 中维护事件定义（D001）。K01 在接入方 CI 中对比 git 基线版本，按下表判断兼容性。破坏性变更必须递增 `schema_version`，并由接入方的数据负责人在代码评审中批准；兼容变更也要递增 `schema_version`。K01 只做判定和拦截，审批流程由接入方的代码评审承担。

| 变更 | 判定 |
|---|---|
| 新增可选字段 | 兼容 |
| 新增必填字段 | 破坏性 |
| 删除字段 | 破坏性 |
| 修改字段 `type` 或 `kind` | 破坏性 |
| 可选改为必填 | 破坏性 |
| 必填改为可选 | 兼容 |
| `enum_values` 增加取值 | 兼容 |
| `enum_values` 删除取值 | 破坏性 |
| 放宽 `max_length`、`minimum`、`maximum` | 兼容 |
| 收紧 `max_length`、`minimum`、`maximum` | 破坏性 |
| 修改 `unit` | 破坏性 |
| 修改 `sensitivity` 为更严格的值（none → mask → hash → drop） | 兼容 |
| 修改 `sensitivity` 为更宽松的值 | 破坏性，另需接入方安全负责人批准 |
| `priority` 由 normal 改为 critical | 兼容，需满足 Q3 的判定标准与 K01 配额检查（K01-F3） |
| `priority` 由 critical 改为 normal | 兼容 |
| 只修改 `description`、`trigger`、`owner` | 不递增版本 |

修改了字段而没有递增 `schema_version` 时，K01 返回非零退出码（K01-AC-04）。

## 运行期校验（接收方，可选）

K01 导出校验规则 JSON（K01-F5），接收方可以用它做运行期校验（RR-22）。建议接收方：

- 按 `event_name` + `schema_version` 查找定义，查不到时标记为未登记后入库，不丢弃；
- 必填字段缺失、类型不符、枚举值不在列表中的事件单独存放或计数，不静默丢弃（RR-21）；
- 定义中没有的字段丢弃该字段并计数；
- 至少保留每个事件最近 3 个 `schema_version` 的规则，保证未升级的客户端仍能入库。

以上是建议，本项目不验证接收方的实现。

## 类型包生成（K01-F4）

- K01 在接入方仓库中生成类型声明文件，由接入方自己提交或发布，不需要本项目发布类型包。
- 对每个 `active` 状态的事件，生成其最新版本的类型：必填字段为必需属性，`enum` 生成字面量联合类型，`boolean` 维度生成 `boolean` 并由 SDK 序列化为字符串；事件名携带投递等级与 `schema_version`。
- 生成结果只包含类型声明，运行时零代码。
