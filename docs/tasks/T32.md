# T32 可靠性对账测试（10 万个会话模拟，对接 M01）

- 阶段 / 执行 Agent / 对接负责人*：P5 / A10 / 质量负责人

## 目标*
模拟 10 万个会话（含断网、强杀、多标签页），对比 SDK 发送计数与 M01 去重后入库计数，得出 SDK 一侧的丢失率和重复送达率。

## 验收用例*
- 丢失率按 **D004 的三类分列**统计，**不得合并成一个丢失率**：① 有优雅退出路径的场景（页面离开/隐藏、断网恢复、多标签页、优雅关闭）critical 不超过 0.1%、normal 不超过 1%；② 硬杀场景下**已确认落盘**（IndexedDB 事务 `oncomplete` 已返回）的 critical **不丢**；③ 硬杀**暴露窗口内未提交**的事件按条数与窗口时长计量（不设丢失率指标，实测窗口为毫秒量级）。
- 以上均以 M01 去重后入库计数为准。
- 重复送达率（M01 去重前减去重后）如实报告，作为 `receiver-requirements.md` RR-05 必要性的依据，不设上限。
- 场景构成写明比例：正常、页面关闭、强杀、断网 1–30 分钟、2–5 个标签页；M01 故障注入比例写明。
- 丢失事件按原因码归类，能解释每一类的来源。
