# T02 POC-1 投递可靠性

- 阶段 / 执行 Agent / 对接负责人*：P0 / A04 / 前端负责人（结对）
- 依赖任务及验收状态*：无
- 截止时间：2026-10-30

## 目标*
用最小原型测出页面离开、浏览器强杀、断网、多标签页四类场景下的实际丢失率，验证 critical 预写加补发的方案能否达到丢失率目标，为 T16 提供依据。

## 需求编号*
C07-F1、C07-F5、C07-F6、C07-F7（验证可行性，不要求完整实现）。

## 契约引用*
`docs/contracts/ingest-protocol.md` 0.1 草案（只用于 POC，不作为实现依据）。

## 上下文切片*
- 总体方案：C06、C07、性能指标汇总中的可靠性指标、风险 R02 与 R06
- 本仓库无现有代码

## 文件所有权*
- 可写：`poc/poc-1/`、`docs/poc/POC-1.md`
- 只读参考：`docs/contracts/`
- 禁止修改：`packages/`（POC 代码不进入正式包）

## 验收用例*
POC 报告使用 `docs/templates/poc-report.md`，必须包含：
- 四类场景在 Chromium、Firefox、WebKit 下各至少 1,000 次的结果，分 normal 和 critical 统计丢失率；
- 信标、fetch keepalive、`visibilitychange` 与 `pagehide` 冲刷的对比；
- Web Locks 与 BroadcastChannel 两种选主方式在多标签页下的重复补发率；
- 是否达到 critical 丢失率不超过 0.1%、normal 不超过 1% 的明确结论。
