# 规格线 → 验证落点台账

> **一句话**：这张台账把 `tests/acceptance/*.md` 里每一条**可执行验收判据**映射到**一条真的跑得到的检查**（文件 + 用例名，或 pnpm 脚本），并由 `scripts/spec-line-check.mjs` 机器校验。**没有可验证回执的移交，不算移交。**

## 0. 怎么读

- **来源**：`tests/acceptance/<文档>.md:<行号>`。机器校验会重读该行，确认它仍以该用例 ID 开头；源文件插行/改行会红。
- **原文**：该验收行「预期结果」单元格原文（未改写）。
- **类型**：`数值` / `功能`，口径见 [`spec-line-inventory.md`](spec-line-inventory.md) §0。
- **验证落点**：可执行检查。格式：
  - `vitest:<path> :: <完整用例名>`：由 `vitest list` 证明该文件被某个 project 收集、该用例名存在；`pnpm test` 会执行（`unit` / `contract` / `security` / `compat`）。
  - `script:<package.json> :: <script 名>`：脚本名必须在清单里，且命令里的入口文件必须存在；`进 gates` 列写明它由哪一步传递执行。
  - `e2e:<path> :: <用例标题>`：Playwright 用例；静态匹配标题，且文件在 `playwright.config.ts` 的 `testDir` 内。**e2e 不进 `pnpm gates`**。
  - 多个落点用 ` ;; ` 分隔；每个都必须可达。
- **进 pnpm gates**：`是（pnpm …）` 表示该检查由 gates 链里的某一步执行；`部分（…）` 表示主落点在 gates、附加落点不在；`否（…）` 表示不在。机器会核对 `是` / `部分` 里写的 `pnpm <step>` 确实出现在 `gates` 脚本里。
- **状态**：
  - `verified`：至少一个可达落点；机器只证明「跑得到」，不证明「达标」——达标看该检查的输出。
  - `pending`：**已知无落点**，显式挂账。默认运行（严格）会红；门禁命令 `pnpm spec:check` 用 `--allow-pending` 放行，但**逐条打印 pending 原文**，不静默。
  - 空落点且非 `pending`：必红。

## 3. 机器校验能抓住什么 / 抓不住什么

### 能抓住

1. **落点为空**：`verified` 行的落点列是 `—` ⇒ 红。
2. **落点不可达**：
   - `vitest`：文件不在 `vitest list` 里（被删 / 改名 / 移出 project include）⇒ 红；用例名不在该文件的列表里（改名）⇒ 红。
   - `script`：清单里没有该脚本名、命令里的入口文件不存在、或 `gates` 链里没有声称的门禁步骤 ⇒ 红。
   - `e2e`：文件不存在、标题不在源文件里、或文件不在 `playwright.config.ts` 的 `testDir` 内 ⇒ 红。
3. **反向漂移**：台账里指向的检查被删/改名 ⇒ 同上红。
4. **来源漂移**：`tests/acceptance/<文档>.md:<行号>` 不再是该用例行 ⇒ 红。
5. **空转**：台账一条都没解析出来（解析器坏了 / 表被清空 / 表头变了）⇒ 红，**绝不把「0 条」当全绿**。
6. **静默 pending**：`pending` 行必须在门禁输出里逐条出现；`--allow-pending` 只放行退出码，不放行可见性。

### 抓不住

- **判据强度**：机器只能证明「这条用例/脚本存在且被收集」，不能证明它**断言了原文那个阈值**。例如 `M01-AC-14` 的单元测试里写着「规格线『30 秒 ≥ 500 批/秒』不在单元门禁」——机器会把它当可达落点；台账因此**不把它写成 verified**，而是 `pending`。这正是本台账要防的「有检查，但检查的不是这条规格线」。
- **达标**：`≤2 s` 是否真的达到、`≥500 批/秒` 是否真的跑到，要看检查输出；台账只负责「有人跑这条判据」。
- **组织归属**：台账不接受「由 T20 负责」「移交 T32」这类结论；落点必须是路径 + 用例名/脚本命令。组织结论只能出现在备注里，且不能替代落点。

## 4. 与门禁的关系

- `package.json` 新增 `spec:check`：`node scripts/spec-line-check.mjs --allow-pending`，并插入 `gates` 链（位置见 `package.json`）。**这是门禁配置变更，需负责人追认。**
